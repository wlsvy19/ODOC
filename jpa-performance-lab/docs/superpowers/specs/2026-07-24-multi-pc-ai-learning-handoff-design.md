# 여러 PC·AI 간 JPA 학습 인계 설계

## 1. 목적

`ODOC/jpa-performance-lab`에서 진행하는 JPA 학습을 여러 데스크톱 PC에서 이어간다. 각 PC에서는 Git으로 최신 상태를 받은 뒤 Codex를 기본 AI 도구로 사용하고, 필요하면 Claude Code도 동일한 학습 맥락을 이어받는다.

채팅 기록이나 특정 PC의 로컬 상태는 신뢰 가능한 인계 수단으로 사용하지 않는다. Git에 커밋된 코드와 학습 문서를 유일한 기준으로 삼는다.

## 2. 범위

이 설계는 다음을 포함한다.

- Codex와 Claude Code가 프로젝트의 공통 학습 상태를 읽는 진입 파일
- 고정된 학습 로드맵, 현재 상태, 기술 결정 기록
- 새 PC에서 학습을 시작하는 절차
- 학습 세션을 마칠 때 상태를 인계하는 절차
- 문서와 실제 코드가 어긋났을 때 복구하는 규칙

다음은 이번 범위에 포함하지 않는다.

- 대화 기록 전체 보관
- AI 공급자별 프롬프트 내용 복제
- 비밀번호와 API 키 같은 비밀정보의 Git 저장
- 자동 커밋 또는 자동 푸시
- JPA 게시판 기능 자체의 구현

## 3. 저장소 구조

`ODOC`은 여러 실습 프로젝트를 포함하는 모노레포로 유지한다. 학습 인계 파일은 `jpa-performance-lab` 디렉터리 아래에만 둬서 다른 실습 프로젝트에 영향을 주지 않는다.

```text
ODOC/
└── jpa-performance-lab/
    ├── AGENTS.md
    ├── CLAUDE.md
    ├── README.md
    └── docs/
        └── learning/
            ├── ROADMAP.md
            ├── STATUS.md
            └── DECISIONS.md
```

## 4. 파일별 책임

### 4.1 `AGENTS.md`

Codex의 프로젝트 진입 파일이다. 다음 규칙을 포함한다.

- 응답이나 작업 전에 `README.md`, `docs/learning/STATUS.md`, `docs/learning/ROADMAP.md`, `docs/learning/DECISIONS.md`를 읽는다.
- 세션 시작 시 현재 단계, 완료된 내용, 다음 한 단계를 먼저 요약한다.
- 사용자가 직접 실습한다는 원칙을 존중하고, 요청하지 않은 코드를 대신 작성하지 않는다.
- 한 번에 한 학습 단계만 안내하고 실행 결과를 확인한 뒤 다음 단계로 넘어간다.
- 코드 변경이 있으면 관련 테스트나 실행 결과를 확인한다.
- 세션 종료 또는 의미 있는 단계 완료 시 `STATUS.md` 갱신을 제안한다.
- 새로운 기술 선택이 생기면 `DECISIONS.md` 갱신을 제안한다.
- 새로 만드는 Git 커밋 메시지의 제목과, 본문이 있으면 본문을 한글로 작성한다. 기술 식별자와 명령어는 필요한 경우 원문을 유지한다.
- 원격 저장소에 푸시하기 전에 푸시 범위와 커밋 메시지를 확인한다. AI가 만든 미푸시 커밋의 메시지가 한글이 아니면 한글로 고치되, 기존 사용자 커밋 이력은 임의로 다시 작성하지 않는다.
- 비밀정보를 출력하거나 학습 문서에 기록하지 않는다.

### 4.2 `CLAUDE.md`

Claude Code의 프로젝트 진입 파일이다. 세부 학습 상태를 중복 기록하지 않고 공통 문서들을 읽도록 지시한다. Codex와 Claude Code 사이에서 서로 다른 상태가 생기지 않도록 `AGENTS.md`와 동일한 학습 원칙을 간결하게 유지한다.

### 4.3 `README.md`

사람과 AI가 모두 사용하는 실행 안내서다.

- 프로젝트 목적과 기술 스택
- Java 및 Gradle 요구사항
- 애플리케이션 실행 명령
- 테스트 명령
- 데이터베이스 연결 방식과 필요한 환경
- Actuator 상태 확인 주소
- 새 PC에서 저장소를 받은 뒤 최초 실행하는 절차

비밀번호의 실제 값은 기록하지 않는다.

### 4.4 `docs/learning/ROADMAP.md`

쉽게 바뀌지 않는 전체 학습 순서를 관리한다.

초기 로드맵은 다음 단계로 구성한다.

1. 프로젝트 및 데이터베이스 연결
2. `Post` 엔티티와 기존 `jpa_study.posts` 테이블 매핑
3. Spring Data JPA Repository
4. 게시글 등록과 조회
5. 게시글 수정과 삭제
6. Thymeleaf 게시판 화면
7. JPA 테스트
8. 페이징과 검색
9. Actuator 관측
10. k6 기반 Smoke·Baseline 부하 테스트
11. 쿼리 및 인덱스 개선 전후 비교

각 단계는 `대기`, `진행 중`, `완료` 중 하나의 상태를 갖는다.

### 4.5 `docs/learning/STATUS.md`

새 AI 세션이 가장 먼저 확인하는 현재 상태 문서다. 과거 전체 기록이 아니라 바로 이어서 작업하는 데 필요한 최소 정보만 유지한다.

필수 항목은 다음과 같다.

- 마지막 갱신일
- 현재 학습 단계
- 완료된 작업
- 현재 확인된 실행 결과
- 다음에 할 정확한 한 단계
- 알려진 문제 또는 막힌 점
- 다음 단계의 완료 조건

`STATUS.md` 내용과 실제 코드가 다르면 코드, 테스트 결과, Git 이력을 확인해 문서를 정정한 뒤 진행한다.

### 4.6 `docs/learning/DECISIONS.md`

반복해서 논의할 가능성이 있는 기술 결정을 기록한다.

초기 결정에는 다음이 포함된다.

- `ODOC` 모노레포 안에서 프로젝트 유지
- 프로젝트명 `jpa-performance-lab`
- Java 26
- Spring Boot 4.1.0
- Gradle Groovy DSL 및 Wrapper 9.5.1
- Thymeleaf 기반 서버 렌더링
- Supabase GDTCS 프로젝트의 `jpa_study` 스키마 사용
- Hibernate 스키마 정책 `ddl-auto=validate`
- Supavisor Session Mode 5432 사용
- 초기 HikariCP 최대 크기 5

각 결정에는 날짜, 결정 내용, 이유, 향후 변경 조건을 기록한다.

## 5. 세션 시작 흐름

1. 사용자가 `ODOC` 저장소에서 현재 브랜치와 미커밋 변경을 확인한다.
2. 안전하게 최신 커밋을 가져온다.
3. AI는 프로젝트 범위의 진입 파일과 공통 학습 문서를 읽는다.
4. AI는 코드와 문서가 일치하는지 Git 상태와 최근 커밋으로 확인한다.
5. AI는 다음 세 항목만 먼저 보고한다.
   - 지금까지 완료된 것
   - 현재 단계
   - 이번 세션에서 할 한 가지
6. 사용자의 확인 후 실습을 시작한다.

미커밋 변경이 있으면 AI는 먼저 그 변경이 어느 PC 또는 세션에서 만들어졌는지 확인하고, 덮어쓰기나 정리를 임의로 수행하지 않는다.

## 6. 세션 종료 및 인계 흐름

의미 있는 학습 단계가 끝나면 다음 순서를 따른다.

1. 실행 또는 테스트 결과를 확인한다.
2. `STATUS.md`에 완료 내용과 다음 한 단계를 갱신한다.
3. 기술적 선택이 생겼으면 `DECISIONS.md`를 갱신한다.
4. `git diff`로 코드와 문서의 범위를 확인한다.
5. 코드와 관련 학습 문서를 하나의 의도적인 커밋으로 묶는다.
6. 새 커밋 메시지를 한글로 작성하고, 푸시할 커밋의 메시지가 한글인지 확인한다.
7. 사용자가 푸시를 요청하면 원격 저장소에 푸시한다.

다른 PC에서는 원격 저장소에 푸시된 상태만 이어받을 수 있다. 따라서 커밋하지 않은 작업이나 로컬 채팅 내용은 인계된 것으로 간주하지 않는다.

## 7. 충돌 및 오류 처리

### 문서와 코드가 다를 때

실제 코드, 검증 명령 결과, Git 이력을 우선한다. `STATUS.md`를 현재 사실에 맞게 수정한 후 다음 작업을 안내한다.

### 여러 PC에서 동시에 작업했을 때

무조건 `pull` 또는 강제 덮어쓰기를 하지 않는다. 각 PC의 미커밋 변경과 원격 커밋을 확인하고, 충돌 범위를 사용자에게 설명한 뒤 병합한다.

### AI가 다음 단계를 판단할 수 없을 때

추측으로 진도를 넘기지 않는다. `STATUS.md`의 완료 조건, 최근 커밋, 테스트 결과를 확인하고도 불명확하면 사용자에게 한 가지 질문만 한다.

### 검증이 실패했을 때

실패 사실과 실행한 명령, 핵심 오류, 재현 방법을 `STATUS.md`의 알려진 문제에 기록한다. 해결되지 않은 작업을 완료로 표시하지 않는다.

## 8. 보안

- 관리자 비밀번호, API 키, 토큰을 학습 문서나 커밋 메시지에 기록하지 않는다.
- 여러 PC에서 같은 데이터베이스에 연결할 필요가 있으면 `jpa_study`만 접근 가능한 제한 계정을 사용한다.
- 관리자 계정의 비밀번호가 이미 Git 이력에 포함됐다면 해당 비밀번호를 교체한다.
- AI는 비밀값을 화면에 다시 출력하거나 로그에 남기지 않는다.

## 9. 수용 조건

구현은 다음 조건을 모두 만족해야 한다.

1. `jpa-performance-lab`에서 Codex를 시작하면 별도 설명 없이 현재 학습 상태 문서를 찾을 수 있다.
2. Claude Code를 사용해도 동일한 공통 상태 문서를 읽는다.
3. 새 PC에서 저장소를 받은 사용자가 `README.md`만으로 실행 준비를 할 수 있다.
4. `STATUS.md`만 읽어도 완료된 단계와 다음 한 단계가 명확하다.
5. 기술 선택의 이유를 `DECISIONS.md`에서 확인할 수 있다.
6. 어떤 문서에도 실제 비밀번호나 토큰이 포함되지 않는다.
7. 학습 단계 완료 시 코드와 상태 문서를 함께 커밋할 수 있다.
8. AI가 새로 만든 커밋은 한글 커밋 메시지를 사용하며, 푸시 전에 이를 확인한다.
