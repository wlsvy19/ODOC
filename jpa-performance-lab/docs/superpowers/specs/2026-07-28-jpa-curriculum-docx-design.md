# JPA 누적 교재형 커리큘럼 Word 문서 설계

## 목표

`jpa-performance-lab`에서 진행하는 JPA 게시판 학습을 한 개의 Word 문서에 누적한다. 사용자는 어느 PC에서든 Git으로 프로젝트를 받은 뒤 현재까지 배운 내용, 현재 위치, 다음 단계와 전체 학습 방향을 교재처럼 읽을 수 있어야 한다.

## 결과물

- 파일: `docs/learning/JPA_학습_커리큘럼.docx`
- 형식: 단일 누적 교재
- 독자: JPA를 기초부터 성능 실험까지 직접 실습하는 사용자
- 갱신 주체: 사용자 요청을 받은 Codex 또는 Claude Code

문서는 Git으로 추적하지만 학습 상태의 원본 데이터는 기존 Markdown 문서로 유지한다.

## 기준 데이터와 우선순위

AI는 다음 순서로 현재 상태를 확인한다.

1. 실제 소스 코드와 Gradle 테스트 결과
2. `docs/learning/STATUS.md`
3. `docs/learning/ROADMAP.md`
4. `docs/learning/DECISIONS.md`
5. 최근 Git 커밋
6. `JPA_학습_커리큘럼.docx`

코드 또는 Markdown과 Word가 다르면 코드와 Markdown을 기준으로 Word를 정정한다. Word 문서만 보고 완료 상태를 새로 판단하지 않는다.

## 초기 문서 범위

### 1. 문서 사용 방법

- Markdown과 Word의 역할
- 여러 PC에서 학습을 이어가는 방법
- AI에게 현재 상태 확인과 커리큘럼 갱신을 요청하는 문구
- 완료 상태를 바꾸기 전에 필요한 검증

### 2. 프로젝트 학습 환경

- Java 26
- Spring Boot 4.1.0
- Gradle Wrapper 9.5.1
- Spring Web MVC, JSP/JSTL
- Spring Data JPA와 Hibernate
- Supabase PostgreSQL의 `jpa_study` 스키마
- Actuator, P6Spy, k6

실제 DB 사용자명과 비밀번호는 문서에 기록하지 않는다.

### 3. 전체 커리큘럼과 현재 진행률

로드맵을 단계별 표로 정리하고 `완료`, `진행 중`, `대기` 상태를 표시한다. 현재 기준은 다음과 같다.

- 1단계 프로젝트 생성과 DB 연결: 완료
- 2단계 엔티티 매핑: 완료
- 3단계 Spring Data JPA Repository: 완료
- 4단계 게시글 등록과 조회: 완료
- 5단계 게시글 수정과 삭제: 진행 중
- 6단계 JSP 게시판: 목록·상세·등록 완료, 수정·삭제 대기
- 7단계 이후 테스트·검색·관측·부하 테스트·성능 개선: 대기

### 4. 완료한 학습 내용

완료한 항목은 교재형으로 다음 정보를 포함한다.

- 왜 배우는지
- 핵심 개념
- 프로젝트에서 적용한 위치
- 코드 또는 설정 예시
- SQL과 콘솔 로그에서 확인할 점
- 실습 결과
- 자주 발생한 오류와 해결 이유

초기 버전에서 자세히 설명할 완료 항목은 다음과 같다.

- Supabase 전용 스키마와 `posts` 테이블
- Spring Boot·Gradle·PostgreSQL 연결
- `Post` 엔티티와 테이블 매핑
- Repository 전체 조회
- Controller·Service 인터페이스·Service 구현체·Repository 계층
- JSP 목록·상세·등록 흐름
- 엔티티 생성과 수정 행위 메서드
- P6Spy 바인딩 값 포함 SQL
- Gradle `bootRun` UTF-8 출력과 접속 주소 안내
- Git과 학습 문서를 이용한 PC 간 인계

### 5. 현재 학습 단원

게시글 수정과 삭제를 현재 단원으로 표시한다.

- JPA 영속성 컨텍스트
- 트랜잭션 안에서 엔티티 조회
- 엔티티 상태 변경
- 변경 감지와 `UPDATE`
- 수정 폼에 기존 값 표시
- 수정 완료 후 상세 화면 이동
- 실습 데이터 삭제와 `DELETE`
- P6Spy SQL 확인
- 전체 테스트

현재 단원의 다음 한 단계는 `PostService`와 `PostServiceImpl`의 수정 메서드 추가다.

### 6. 이후 학습 단원

아직 시작하지 않은 단원은 상세 본문을 미리 완성하지 않는다. 다음 네 항목만 먼저 기록하고 실제 학습을 시작할 때 확장한다.

- 학습 목표
- 핵심 개념
- 실습 예정
- 완료 조건

초기 이후 단원은 다음을 포함한다.

- Validation 완성
- JPA 테스트
- 트랜잭션과 영속성 컨텍스트 심화
- 페이징·정렬·검색
- 연관관계와 N+1 문제
- Query Method·JPQL·Native Query
- 인덱스와 실행 계획
- Actuator 지표 관측
- k6 Smoke·Baseline·Stress·Spike·Soak
- 성능 개선 전후 비교

공유 Supabase 무료 프로젝트에서는 Smoke와 Baseline까지만 수행하고, Stress·Spike·Soak는 격리된 환경에서만 진행한다고 명시한다.

### 7. 부록

- 실행·테스트 명령어
- 브라우저 접속 주소
- 자주 발생한 오류
- JPA 핵심 용어
- 커리큘럼 변경 이력

## 문서 디자인

문서 유형은 교재와 운영 참고서를 결합한 핸드북이다. `compact_reference_guide` 디자인 프리셋을 사용한다.

- 첫 페이지: 제목, 프로젝트명, 현재 단계, 최종 갱신일
- 본문: 명확한 제목 계층과 짧은 설명 단락
- 진행 상태: 비교 가능한 표
- 실습 순서: 실제 Word 번호 목록
- 주의사항: 절제된 강조 상자
- 코드·SQL·명령어: 본문과 구분되는 고정폭 스타일
- 머리글: 문서명과 현재 장
- 바닥글: 페이지 번호와 최종 갱신일

장식보다 가독성과 반복 갱신의 안정성을 우선한다.

## AI 갱신 규칙

사용자가 다음과 같이 요청하면 AI는 커리큘럼 갱신을 제안한다.

- `커리큘럼에 추가할 내용 알려줘`
- `오늘 진행한 내용을 커리큘럼에 반영해`
- `Word 커리큘럼 갱신해`
- `어디까지 진행했어?`

갱신 절차는 다음과 같다.

1. 실제 코드, 테스트, Git 상태와 Markdown 3개를 확인한다.
2. 완료한 것, 현재 단계, 다음 한 단계를 사용자에게 보고한다.
3. Word에 추가하거나 확장할 항목을 제안한다.
4. 사용자의 승인을 받은 범위만 반영한다.
5. 상태가 바뀌면 Markdown과 Word를 함께 갱신한다.
6. Word를 렌더링해 모든 페이지를 시각적으로 검토한다.
7. 한글 커밋 메시지로 저장한다.
8. 사용자가 명시적으로 요청한 경우에만 원격 저장소에 푸시한다.

단순 오탈자나 코드 경로 정정은 범위를 보고한 뒤 바로 수정할 수 있지만, 새로운 학습 단원 추가나 순서 변경은 사용자 승인을 먼저 받는다.

## 보안과 사실성

- DB 사용자명과 비밀번호를 Word에 기록하지 않는다.
- 실제로 검증하지 않은 기능은 완료로 표시하지 않는다.
- 미래 단원의 예제 코드는 해당 단원을 시작할 때 현재 프로젝트 코드와 버전에 맞춰 작성한다.
- 성능 수치는 측정 환경, 데이터 수, 부하 조건과 함께 기록한다.
- Supabase 공유 프로젝트에 위험한 부하 테스트를 권장하지 않는다.

## 검증

Word 문서를 생성하거나 의미 있게 수정할 때마다 다음을 확인한다.

1. 문서의 현재 단계가 `STATUS.md`와 일치한다.
2. 전체 단계와 상태가 `ROADMAP.md`와 일치한다.
3. 기술 선택 설명이 `DECISIONS.md`와 충돌하지 않는다.
4. 실제 DB 접속정보가 포함되지 않는다.
5. DOCX를 페이지 이미지로 렌더링한다.
6. 모든 페이지에서 한글 글리프, 표, 코드 블록, 줄바꿈, 머리글과 바닥글을 확인한다.
7. 잘림, 겹침, 과도한 빈 공간과 깨진 페이지 나눔이 없을 때만 최종 파일로 전달한다.

## 제외 범위

- Word 문서를 학습 상태의 단일 원본으로 사용하는 것
- 아직 시작하지 않은 모든 단원의 상세 교재를 미리 완성하는 것
- 문서 안에 실제 DB 접속정보를 기록하는 것
- Word를 수정했다는 이유만으로 학습 단계를 완료 처리하는 것
- 사용자 승인 없이 전체 커리큘럼 순서를 크게 변경하는 것
