# PC 간 학습 인계 저장 명령 설계

- 작성일: 2026-07-27
- 대상 저장소: `C:\sw\ODOC`
- 대상 프로젝트: `jpa-performance-lab`
- 명령 문구: `인계 저장`

## 목적

한 PC에서 JPA 학습을 중단하더라도 현재 코드, 검증 결과, 막힌 지점과 다음 한 단계를 원격 `main`에 함께 저장한다. 다른 PC에서는 `git pull --ff-only` 후 Codex나 Claude Code가 공통 학습 문서를 읽고 같은 지점부터 이어서 안내한다.

## 선택한 방식

사용자가 대화에서 정확히 `인계 저장`이라고 말하면 AI가 학습 종료 체크포인트를 만든다. 이 문구는 현재 `jpa-performance-lab` 학습 변경을 검증하고, 관련 문서를 갱신하고, 한글 커밋을 만든 뒤 `origin/main`에 푸시하라는 명시적 승인으로 간주한다.

수동 체크리스트만 사용하는 방식은 단계를 빠뜨리기 쉽고, 의미 있는 단계마다 자동 푸시하는 방식은 사용자가 원하지 않은 중간 상태를 원격에 올릴 수 있어 선택하지 않는다.

## 명령이 허용하는 범위

`인계 저장`은 다음 작업만 허용한다.

- `jpa-performance-lab` 관련 Git 상태와 diff 확인
- 현재 학습 단계에 적합한 테스트 실행
- `docs/learning/STATUS.md` 갱신
- 단계 상태가 바뀐 경우 `docs/learning/ROADMAP.md` 갱신
- 새로운 결정이 생긴 경우 `docs/learning/DECISIONS.md` 갱신
- 현재 학습과 관련된 파일만 스테이징
- 제목과 본문이 한글인 체크포인트 커밋 생성
- 일반 푸시인 `git push origin main` 실행
- 푸시 후 로컬 `HEAD`와 `origin/main` 일치 확인

## 명령이 허용하지 않는 범위

- ODoc의 다른 프로젝트 변경을 함께 커밋
- 출처를 확인하지 않은 기존 사용자 변경을 수정·삭제
- `git reset --hard`, 강제 체크아웃, 강제 푸시
- 자동 충돌 해결 또는 원격 이력 재작성
- DB 접속정보를 응답, 학습 문서나 커밋 메시지에 출력
- 테스트 실패를 성공으로 기록

## 저장 절차

1. 현재 브랜치가 `main`인지 확인한다.
2. `git status --short`, diff, 최근 커밋과 원격 차이를 확인한다.
3. `git fetch origin main`으로 원격 상태를 갱신한다.
4. 원격 `main`이 로컬보다 앞서 있으면 자동 푸시하지 않고 충돌 가능성을 보고한다.
5. 현재 단계의 테스트를 실행한다.
6. 검증된 완료 내용, 현재 단계, 다음 한 단계, 알려진 문제를 `STATUS.md`에 기록한다.
7. 단계가 바뀌었으면 `ROADMAP.md`, 새로운 결정이 생겼으면 `DECISIONS.md`를 함께 갱신한다.
8. `jpa-performance-lab`의 현재 학습 관련 파일만 스테이징한다.
9. `git diff --cached --check`와 스테이징 범위를 확인한다.
10. 학습 내용을 설명하는 한글 커밋을 생성한다.
11. `git push origin main`을 실행한다.
12. `origin/main`과 로컬 `HEAD`가 일치하는지 확인하고 다른 PC의 재개 명령을 안내한다.

## 테스트가 실패한 상태에서의 인계

학습 중단 시점이 TDD의 Red 단계이거나 예상하지 못한 오류가 발생한 상태일 수 있다. 이 경우 실패를 숨기거나 완료로 표시하지 않는다.

- `STATUS.md`의 현재 단계에 실패한 명령과 핵심 원인을 기록한다.
- 다음 한 단계에 실패를 해소하기 위한 정확한 작업을 기록한다.
- 커밋 메시지는 `JPA 학습 중간 상태 저장`처럼 미완료 상태임을 드러낸다.
- 실패 상태도 다른 PC에서 이어갈 필요가 있으므로, 관련 파일과 상태 문서가 안전하면 일반 푸시한다.
- 자격 증명 노출, 관련 없는 변경, 원격 선행 커밋 또는 충돌 위험이 있으면 푸시하지 않고 사용자에게 보고한다.

## 다른 PC에서 재개

다른 PC에서는 먼저 ODoc 저장소의 로컬 변경을 확인한다.

```powershell
Set-Location C:\sw\ODOC
git status --short
git pull --ff-only origin main
Set-Location .\jpa-performance-lab
```

로컬 변경이 있으면 pull 전에 출처와 충돌 가능성을 확인한다. Codex는 `jpa-performance-lab`을 작업 폴더로 열어 `AGENTS.md`, `README.md`, `STATUS.md`, `ROADMAP.md`, `DECISIONS.md`를 읽는다.

재개 시 먼저 다음 세 가지를 보고한다.

1. 지금까지 완료된 것
2. 현재 학습 단계 또는 실패 상태
3. 이번 세션에서 할 한 가지

그다음 `STATUS.md`에 기록된 마지막 검증 명령을 실행하고 다음 한 단계부터 사용자 직접 타이핑 방식으로 진행한다.

## 문서 반영

- `AGENTS.md`에 `인계 저장`의 권한, 안전 조건과 실행 순서를 추가한다.
- `README.md`의 학습 종료와 Git 인계 절차에 명령 문구와 다른 PC 재개 절차를 추가한다.
- `DECISIONS.md`에 전용 인계 명령과 명시적 푸시 승인 의미를 기록한다.

## 완료 조건

- 새 AI 세션이 `인계 저장`의 의미를 문서만 읽고 동일하게 해석한다.
- 명령 실행 후 현재 학습 코드와 상태 문서가 같은 커밋 또는 연속된 안전한 커밋으로 `origin/main`에 존재한다.
- 다른 PC의 clean checkout에서 `git pull --ff-only origin main`으로 해당 상태를 받을 수 있다.
- AI가 다음 한 단계를 추측하지 않고 `STATUS.md`에서 확인한다.
